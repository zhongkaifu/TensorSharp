# GLM diagnostic refusal and reset regression probe

`check-glm-trace-refusal.py` loads a user-selected production native library
through its actual C ABI in an isolated CPU-only child. Use a tiny GLM5Next GGUF
generated by `GlmGraphBudgetProbe`; fixtures over16MiB are refused. This tool
does not build native code, initialize a GPU, download weights or run a real
model quality/performance benchmark.

The default mode gives the optional tensor diagnostic a one-byte process-wide
budget. Two N1 and two real N3 dispatches must refuse without an ABI crash,
return the native trace error, preserve all logits sentinel bytes and slot
heads, publish no completed joint execution, and fence each touched slot until
`ResetChecked` succeeds. Repeating the dispatch proves that reset removes the
fence and that a new refusal fences the state again. The global backend failure
latch must stay clear. All extra slots and the model must release normally.
The preflight refusal leaves an empty capture directory, without a fake
incomplete marker.

```powershell
python eng/validation/check-glm-trace-refusal.py `
  --native E:/TensorSharp-validation-cache/master-merge-20261013/native-v33/build-v1/build-production/GgmlOps.dll `
  --build-receipt E:/TensorSharp-validation-cache/master-merge-20261013/native-v33/build-v1/build-summary.json `
  --fixture-model C:/Works/TensorSharp/artifacts/glm-quality-default-20261014-v1/native33-trace-components-v1/cpu/run/tiny-glm5-next.gguf `
  --library-dir 'C:/Program Files/NVIDIA GPU Computing Toolkit/CUDA/v12.6/bin' `
  --output C:/Works/TensorSharp/artifacts/new-glm-trace-refusal
```

All input paths are explicit. The owned-native build receipt must be successful
and have unchanged source/dependency bookends; the library and implementation
file must match its production/source hashes. The default implementation path
is the build receipt's frozen `source/TensorSharp.GGML.Native/ggml_ops_glm_dsa.cpp`;
`--native-source` supplies an alternative exact matching snapshot. Before/after
SHA256 pins cover the tool, production library, build receipt, source and tiny
fixture. `summary.json`, `child-report.json`, console output, child exit code
and explicit normalized test environment are retained in the fresh output.
Use ignored `artifacts/` or `docs/validation/` for that generated evidence.

On Windows, `--library-dir` adds an existing dependency directory to the child
DLL search path. On Linux/macOS it configures the child library search path.
The native library must already be compatible with that host. Actual evidence
from one OS does not qualify another OS or an Apple device. A CUDA dependency
directory may be needed to load a CUDA-enabled library even though execution is
strictly CPU. The tool uses `CPU` as the native backend and hides CUDA devices.

The `partial-write` mode tests disk-byte ownership after a failed capture.
Supply `--reference-manifest` from an equivalent completed CPU first-pass
capture (`p0=0`, matching `--prefill-rows`, default4). Its exact tensor-byte sum
becomes the process-wide capture limit. The child loads the model, then creates
an owned empty directory at the second binary's temporary filename. The first
tensor must exist when that write refuses, with an incomplete marker and no
committed manifest. After checked reset, the observer removes only its own
empty blocker and retries. The retained first pass must remain charged, causing
the retry to refuse before producing any `pass-000001` files. The existing
partial payload must remain byte-identical throughout subsequent N1/N3 retries.

```text
... --mode partial-write --reference-manifest <equivalent-completed-CPU-pass-000000.json>
```

This mode requires the native implementation to charge failed partial captures
against its process-wide byte budget. A wrong reference shape/budget, a missing
partial file, unexpected retry output, an ABI crash, missing reset fences or any
changed input pin fails the observer. Failure artifacts are preserved.

`python -m unittest discover -s eng/validation/tests -p test_check_glm_trace_refusal.py`
tests the observer against deliberately broken fake native state machines and
tests receipt/environment checks. These pure tests do not count as native,
device, whole-model semantics, physical-limit or performance coverage. This
test verifies application capture-byte accounting; it does not install an OS
filesystem quota or prove physical SSD/RAM/GPU ownership.

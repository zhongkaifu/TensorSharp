如何阅读支持状态

已实现表示代码路径存在；条件支持需要指定变体、后端或伴随文件；实验性表示明确存在实现或验证限制；夹具级验证只覆盖小型合成或组件夹具；已测量仅指记录的检查点、硬件、工作负载与构建；不支持表示被拒绝或尚未实现。输入能力与验证状态需要分别阅读。

按模型卡片选择量化与内存配置。一个量化名称、组件测试或成功加载都不能说明所有设备上的质量与完整运行情况。

工具支持同时要求会声明工具的提示词渲染器与匹配的结构化输出解析器。Qwen 3.8 Flash Next（qwen4exp）通过 Qwen 3.5 解析器返回结构化调用，因此调用者定义的工具、Agent Skills 工具、代码执行工具，以及服务端的子智能体委派都会提供给它。Mistral 3 与 Hunyuan Dense 既不渲染工具声明也不渲染工具结果，DiffusionGemma 不渲染工具声明且会拒绝带工具的请求，因此这三个家族既不会获得上述任何工具，也不参与子智能体委派。

LTX 2.5、MiniMax-H3、Wan 与 DiffusionGemma 拒绝多 GPU 模式。Mistral 3 与 Hunyuan Dense 运行在共享解码运行时上，支持 --tp T、--layer-split P 及两者组合。Qwen 3.8 Flash Next 支持符合量化条件的本地 GGML CUDA TP 与 --layer-split N；DeepSeek V4 使用整层放置。GLM 支持两种显式本地模式；Qwen-Image 仅支持扩散 Transformer 的本地张量并行。DeepSeek V4.1 支持 --layer-split N 与实验性 routed-MoE --tp N。Muse Spark 的原生执行器两种模式都支持——GGML CUDA/Vulkan 上的 --layer-split N 与 GGML CUDA 上的 --tp N——仅限单节点；GGML Vulkan 上的 --tp N 走它的逐算子路径。MiniMax-M3.1 的原生执行器在 GGML CUDA 上两种模式都支持，仅限单节点；它的 --tp N 镜像注意力，并拒绝主机专家与 DSpark 草稿器。

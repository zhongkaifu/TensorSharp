Image Generation & Editing

Qwen-Image-2.1 turns a prompt into an image, or a prompt plus one or more reference images into an edited image. This page covers the download, the run recipe, the defaults, and the settings that decide how long an image takes.

💡

These commands follow the same conventions as the text-model recipes — the Hugging Face CLI, a source build from the repository root, and --backend swapped to match your hardware. See Download & run, per family.

Qwen-Image-2.1 (prompt → image, prompt + image → edited image)

The shortest route is the ready-made config/qwen-image-2.1.json. It pins repository revisions and SHA-256 checksums and downloads whatever is missing — four files, about 10.29 GiB — into $TENSORSHARP_MODELS/qwen-image-2.1/, or models/qwen-image-2.1/ in the repository when TENSORSHARP_MODELS is unset. The configuration selects ggml_metal; on an NVIDIA machine with the CUDA backend built, append --backend ggml_cuda, and the native CPU backend is ggml_cpu.

dotnet build TensorSharp.Cli/TensorSharp.Cli.csproj -c Release
dotnet build TensorSharp.Server.Host/TensorSharp.Server.Host.csproj -c Release

# Text-to-image
dotnet run --project TensorSharp.Cli -c Release --no-build -- \
  --config config/qwen-image-2.1.json \
  --prompt 'A small orange cat beside a blue ceramic vase, soft daylight, detailed photograph' \
  --width 2048 --height 2048 --diffusion-steps 40 --cfg 1 \
  --diffusion-seed 42 --output generated.png

# Image editing
dotnet run --project TensorSharp.Cli -c Release --no-build -- \
  --config config/qwen-image-2.1.json \
  --image generated.png \
  --prompt 'Change the blue vase to a red vase. Preserve the cat, lighting and composition.' \
  --width 2048 --height 2048 --diffusion-steps 40 --cfg 1 \
  --diffusion-seed 42 --output edited.png

# Server + Web UI
dotnet run --project TensorSharp.Server.Host -c Release --no-build -- \
  --config config/qwen-image-2.1.json --host 127.0.0.1 --port 5000

The download size is not peak inference memory: runtime memory also includes activations, decoding buffers and working weights, and larger images and multiple references increase it.

Other Qwen-Image-2.1 GGUFs load as well. A file with no metadata at all, such as Unsloth's qwen-image-2.1-Q8_0.gguf (tensors under a model.diffusion_model. prefix included), is recognized from its tensor layout — never from its file name. The companion scan matches a qwen_image_2.1_vae safetensors file and names containing qwen3vl-8b or qwen3-vl-8b, so a projector saved as mmproj-BF16.gguf needs --qwen-image-mmproj. On an M5 Pro the Unsloth Q8_0 file generated 1024×1024 at 40 steps in 337.7 s, against 383.1 s for stable-diffusion.cpp in the same single-run comparison. Only 2.1 loads: an earlier Qwen-Image or Qwen-Image-Edit-2511 transformer is refused at load (exit code 2).

Image generation & editing (Qwen-Image-2.1)

The loaded qwen_image GGUF is the Qwen-Image-2.1 diffusion transformer. TensorSharp resolves its companions next to it — the dedicated 2.1 VAE, the Qwen3-VL-8B text encoder and, for editing, the Qwen3-VL mmproj vision encoder — or takes them from --qwen-image-vae / --qwen-image-vl / --qwen-image-mmproj (env: TS_QWEN_IMAGE_VAE / TS_QWEN_IMAGE_TE / TS_QWEN_IMAGE_MMPROJ). Native RGBA input and PNG output preserve transparency: the Qwen3-VL conditioning branch composites the reference over white while the VAE keeps alpha.

  • Generation or editing. No --image selects generation; one or more --image arguments select editing, with the references in the order given. --input prompt.txt can supply the prompt instead of --prompt.
  • Sampling defaults. Omitted settings select 40 Euler steps and CFG 1.0, following Qwen's recommended unguided sampling — one transformer prediction per step. An explicit CFG above 1 adds the negative prediction and applies --negative-prompt; negative prompts have no effect at CFG 1.
  • Geometry. Omitting dimensions selects 2048×2048 for generation, or approximately the same pixel area at the first reference's aspect ratio for editing. Set width and height together, in multiples of 32, to override it. On the server, --width and --height (both are needed) set that default for requests that name no size — and the Web UI names none. References are conditioned at approximately 1 megapixel each, or the output area if smaller.
  • Schedule. The official scheduler configuration: exponential dynamic shifting with the 256/0.5 and 8192/0.9 sequence-length/shift anchors, terminal stretching to 0.02, and a final Euler step to zero.
  • Execution. The diffusion transformer runs a complete GGML graph with resident quantized weights, so it needs a GGML backend (ggml_metal, ggml_cuda, ggml_vulkan or ggml_cpu). CUDA and Metal retain the graph between predictions (TS_QWEN21_GRAPH_REUSE=1, the default). There is no CPU weight-streaming mode; start with smaller dimensions if memory is short. The VAE decodes as one whole graph by default on CUDA and Metal — 1024×1024 in 5.0 s on an M5 Pro, against 13.0 s per convolution — and per convolution, on the device, under Vulkan, where inputs are rescaled by exact powers of two to stay within Vulkan's F16 matrix operands; TS_QWEN21_VAE_FUSED=0 selects the per-convolution path anywhere. --tp N shards the transformer across GPUs (see below). LoRA plug-ins run on all four backends (see below).

The speed levers are resolution and step count. The biggest cut in steps is a step-distillation LoRA plug-in, which replaces the 40-step default with 4–8 transformer passes: on an M5 Pro, 1024×1024 at Viggle Turbo's 6 steps took 54.5 s end to end (see LoRA plug-ins). A 2K square has four times the latent image tokens of a 1K square and more attention work, so --width 1024 --height 1024 is the draft setting. --diffusion-steps 25 --cfg 1 is the faster profile used by the official ComfyUI generation and editing workflows; 40 steps remains the default, and fewer steps are a quality/speed trade-off rather than equivalent quality. CFG 1 already means one transformer pass per step. For a quick smoke test, 256×256 and one step verifies loading and the end-to-end data path, not image quality. Editing also gains from the default-on prefix KV cache.

Run it from the CLI (--prompt, plus --image to edit), the Web UI (a prompt without an attachment generates an image; attach one or more images to edit, with live denoising previews), the HTTP API (/api/image-generate and /api/image-edit, each with a /stream variant), or in-process from C# via QwenImageModel.GenerateImage() / EditImage(). Image operations are serialized because the diffusion pipeline shares mutable working state. Full details and the validation history are in the repository's Qwen-Image-2.1 card.

Prefix KV cache

The text and reference-image tokens are modulated at t = 0 and never attend to the image being generated, so their keys and values are the same at every denoising step. TensorSharp implements the official prefix KV cache: step 1 runs the whole sequence and stores each block's prefix keys and values on the device, and every later step runs only the target image's tokens. It is on by default (TS_QWEN21_PREFIX_CACHE=0 turns it off) and stores exactly what attention reads — F16 on Metal and with CUDA flash attention, F32 otherwise — so with the default storage the output PNGs were byte-identical to uncached runs. A CFG run keeps one cache per branch, and every cache is released before the VAE decode. The cost is memory: 512 KiB per prefix token per branch in F16, about 2 GiB for each 1-megapixel reference. A cache may use at most half the memory the device reports free (TS_QWEN21_PREFIX_CACHE_MAX_MIB caps it further) and is otherwise declined with a warning; TS_QWEN21_PREFIX_CACHE_TYPE=q8_0 or q8_0_v stores it in 8 bits, saving memory at 5–13% more time per step and a small rounding of the output.

It pays in proportion to the prefix's share of the sequence. A 1024² edit on an M5 Pro went from 17.97 s to 9.65–10.38 s per step with one reference, and from 33.32 s to 11.46 s with two (2.91×); on an A40 (ggml_cuda) the one-reference edit went from 2.547 s to 1.328 s. Generation, whose prefix is only the prompt, gains 1–3%, and at 2048² editing gains less because the target dominates. Details and the Vulkan numbers are in the Qwen-Image-2.1 card.

Multiple GPUs

--tp N on ggml_cuda or ggml_vulkan shards the diffusion transformer Megatron-style: each GPU holds 32/N whole attention heads and 12,288/N MLP columns, the two row-parallel products in each block are summed across GPUs, and each GPU caches the prefix of its own heads. N must divide the 32 heads — 2, 4, 8 or 16 on one machine — and each weight's quantized blocks must stay whole when it is sharded, which the load checks per weight type; only 2 GPUs have been measured. The text encoder, vision encoder and VAE stay on the first GPU, and multi-node groups are refused. On two A40s it measured 1.34× per step for 1024² generation, 1.42× for a one-reference 1024² edit and 1.54–1.57× at 2048²; under ggml_vulkan, which reduces through host memory, it was 0.86× — slower than one GPU. Partial sums are added in a different order, so outputs are not bit-identical to a single GPU: composition and quality match, while details can differ. See the card for memory per GPU and the numerical checks.

LoRA plug-ins

--lora adds a LoRA to the diffusion transformer on the CLI and the server alike: a style, an editing skill, or a step-distillation adapter that replaces the 40-step default with 4–8 transformer passes. Repeat it to stack plug-ins; --lora-scale sets the strength of the preceding --lora and --lora-config names its companion config (a TensorSharp LoRA config, a PEFT adapter_config.json or a VideoX-Fun pdd_config.json). The twelve ready-made plug-ins in config/lora/ download and hash-check their weights on first use and carry the adapter's strength and sampling recipe.

# Viggle Turbo: 6 steps and CFG 1 from the plug-in's recipe (4–8 steps supported)
dotnet run --project TensorSharp.Cli -c Release --no-build -- \
  --config config/qwen-image-2.1.json \
  --lora config/lora/qwen-image-2.1-viggle-turbo.json \
  --prompt 'A small orange cat beside a blue ceramic vase, soft daylight, detailed photograph' \
  --width 1024 --height 1024 --diffusion-seed 42 --output turbo.png

# The server applies its startup set to every image request
dotnet run --project TensorSharp.Server.Host -c Release --no-build -- \
  --config config/qwen-image-2.1.json --lora config/lora/qwen-image-2.1-pruna-8step.json
  • Shipped plug-ins. Step distillation: viggle-turbo (6 steps, 4–8 supported), pruna-8step, pruna-5step and fun-acc-4step (a PDD bundle with per-step output heads). Styles and editing skills: film-stills, grainscape, fix (DoRA), detail-enhancer, natural-exposure, anime-consistency, object-remover and object-mover. Each file's comments cite its model card, trigger phrase and license; several are non-commercial.
  • Sampling precedence. Explicit --diffusion-steps / --cfg (or a request's steps / cfg) win over the plug-in's recipe, which wins over the model defaults. A step count the recipe has no schedule for is refused, naming the supported ones, and only one plug-in per run may carry a recipe.
  • Formats. Diffusers / PEFT, ComfyUI / ai-toolkit, DiffSynth / ModelScope and kohya names; alpha from per-module .alpha tensors, the PEFT metadata a diffusers saver embeds in the file, an adapter_config.json or the plug-in's own alpha, and otherwise equal to the rank — kohya's ss_network_alpha is training metadata and is ignored, as in ComfyUI and diffusers; DoRA; VideoX-Fun PDD bundles. LoKr, LoHa, text-encoder LoRAs and LoRAs made for other models are refused with a message; nothing is skipped silently.
  • Execution. Applied unmerged, y = W x + B (A x), on top of the quantized weights, because merging a distillation LoRA's small delta into Q8_0 or Q4 weights rounds most of it away. Works with the prefix KV cache and with --tp N, where each GPU holds its slice of the factors.
  • Server. The startup set applies to every generation and edit; per-request LoRA selection is not implemented.

The flag reference and the plug-in config format are in the repository's USAGE.md, and the packing and tensor-parallel details in the Qwen-Image-2.1 card.

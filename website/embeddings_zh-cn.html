嵌入模型与语义检索

将文本与代码转换为向量，用于语义检索和 RAG。TensorSharp 在本地运行 GGUF BERT / XLM-R 编码器，通过兼容 OpenAI 与 Ollama 的 HTTP API 提供嵌入。此功能来自当前源码，较早的发布归档不一定包含。

启动服务

支持 100% 纯 C# cpu，以及原生 ggml_cpu、ggml_metal 与 ggml_cuda 嵌入路径。纯 C# 执行无需原生推理库；原生执行须构建对应后端。每个进程常驻一个编码器；聊天服务使用另一个端口。

dotnet build TensorSharp.Server.Host -c Release \
  -p:TensorSharpSkipGgmlNative=true -p:TensorSharpSkipMlxNative=true
dotnet TensorSharp.Server.Host/bin/TensorSharp.Server.Host.dll \
  --model models/embeddings/snowflake-arctic-embed-l-v2.0-q8_0.gguf \
  --embeddings --backend cpu --embedding-threads 8 \
  --host 127.0.0.1 --port 5000 --no-webui

--embedding-context-size N 可缩小每条输入的 token 上限；0 使用模型元数据。 /v1/models、/api/tags、/api/show 报告当前模型与嵌入能力。嵌入服务不做生成：向 /v1/chat/completions、/v1/responses、/v1/systemone、/v1/videos/generations、/api/generate、/api/chat、/api/chat/ollama、/api/models/load，或 /api/image-generate、/api/image-edit、/api/video-generate（及其 /stream 形式）发送 POST 会返回 HTTP 400，并提示改用 /v1/embeddings 或 /api/embed。显式指定本机没有的 --backend 时以退出码 2 结束，并打印 error: model load refused: …。--embeddings 还要求提供 --model，且不接受 --mmproj。

HTTP API

curl http://127.0.0.1:5000/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"snowflake-arctic-embed-l-v2.0-q8_0","input":["query: read a file","def read_file(path): return open(path).read()"],"dimensions":256}'

curl http://127.0.0.1:5000/api/embed \
  -H 'Content-Type: application/json' \
  -d '{"model":"snowflake-arctic-embed-l-v2.0-q8_0","input":["query: read a file","open a document"],"truncate":false}'

curl http://127.0.0.1:5000/api/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"snowflake-arctic-embed-l-v2.0-q8_0","prompt":"query: read a file"}'

OpenAI 的 input 接受字符串、字符串数组、一个 token ID 数组或 token ID 数组的数组；token 输入须已包含本模型的特殊 token。encoding_format 为 float 或 base64（小端 float32）。返回索引、向量与 token 用量。每次请求最多 2048 条输入、总计 262144 个 token。嵌入及模型信息查询的 JSON 请求体上限为 16 MiB，超限返回 HTTP 413。

OpenAI 拒绝超长输入。Ollama /api/embed 接受字符串或字符串数组，truncate 默认 true，截断保留末尾特殊 token；设为 false 则报错。响应包括 embeddings、纳秒计时和 prompt_eval_count。旧版 /api/embeddings 使用 prompt，返回单个 embedding。

并发调用按 FIFO 顺序合并已等待的请求，每次编码器调用最多 64 条序列与 4096 个 token。第一个请求立即执行，不人为等待；更大的完整请求单独执行。每个调用者保留自己的结果顺序与选项；取消一个调用者不影响仍需结果的其他调用者。见请求调度约定。

检索质量与性能

Snowflake 查询添加 query: 前缀，文档不添加。向量作 L2 归一化，可直接用点积计算余弦相似度。dimensions 截取前若干维后重新归一化；Snowflake 的 Matryoshka 训练支持缩减到 256 维，任意缩减其他模型的维数可能降低质量。MiniLM 上游默认句长短于此 GGUF 的 512 位置容量。代码宜按函数/类边界分块，换模型或分块策略后重建索引。

两种实现都使用完整双向注意力与模型指定的池化。每个纯 C# 模型拥有常驻工作线程池；ARM Q8 投影使用四 token × 四输出的有符号点积 SIMD 块。托管 FP32 注意力转置 key，在 SIMD 通道内按相邻 key 同时计算四个 query，并将 value 按通道块打包（ARM 上每块四个通道）以进行融合乘加。便携向量宽度与四 query 点积回退适配其他处理器及 head 维度，带 padding 的 key 跨度处理尾部；长序列路径采用 64 query × 128 key 分块、ARM 四 query × 十六输出 SIMD 复用与在线 FP32 softmax，每个 head 的临时空间有界。短序列与回退路径保留四行临时分数。原生执行器对 GPU 异长序列打包并用掩码隔离各序列，CPU 投影紧凑打包而注意力独立 padding，并复用计算图。

分词经过独立 HuggingFace 与 llama.cpp 参照验证，包括多语言 Unicode；完整指南记录了上游差异。无原生推理库宿主检查会删除自定义原生资源，并在推理后检查加载的库。托管 x86 路径在硬件支持时使用 AVX/AVX2/AVX-512；四 query × 十六列内核专用于 ARM。当前耗时证据来自 Apple Silicon，尚未测量 x86 性能。性能结论以相同 GGUF、同一硬件和相同请求的实测为准。

C# 集成

Backend = "CPU" 默认选择纯 C# 编码器；"GGML_CPU" 选择原生 CPU，"METAL" 选择原生 Metal，"CUDA" 选择原生 CUDA。

using TensorSharp.Models.Embeddings;

using var model = EmbeddingModel.Load("models/embeddings/all-MiniLM-L6-v2-Q8_0.gguf",
    new EmbeddingModelOptions { Backend = "CPU", Threads = 8 });
EmbeddingBatchResult batch = await model.EmbedAsync(new[] { "read a file", "open a document" });
float[] vector = batch.Embeddings[0];
